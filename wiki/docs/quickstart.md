# Начало

## Установка и запуск

### Получение репозитория

```bash
git clone --recursive https://github.com/blabtm/v2k.git
```

### Настройка окружения

Для работы с проектом требуется только [Docker](https://docs.docker.com/engine/install). Все остальные зависимости включены с контейнер разработки.

Получить контейнер:

```bash
docker pull ghcr.io/blabtm/v2k.dev:latest
```

Подробную информацию о том, как настроить рабочее окружение с использование контейнера разработки можно найти в [руководстве](@site/docs/guides/environment.md). О том, как устроен контейнер -- [основы](@site/docs/basics/environment.md).

> Для ознакомительных целей можно запустить контейнер вручную и получить доступ к оболочке:
>
> ```bash
> docker run -it --mount type=bind,src=.,dst=/workspaces/v2k ghcr.io/blabtm/v2k.dev:latest
> ```

### Инициализация

При первой настройки платформы требуется инициализировать проект. Будут созданы необходимые конфигурационные файлы, временные директории и прочие вспомогательные сущности.

```bash
task platform:init
```

### Конфигурация

Для быстрой конфигурации предусмотрены файлы с переменными окружения, расположенные в `platform/env`. Для начала нужно отредактировать только три переменные, оставив остальные без изменений:

- `NETWORK_ADDR` -- адрес локальной сети, например `192.168.0.0/24`
- `LOCALHOST` -- адрес тестовой машины в локальной сети, например `192.168.0.37`
- `REPO_PATH` -- абсолютный путь до репозитория, например `/home/paraskun/v2k`

Рекомендуется проверить порты, установленные по умолчанию. Если возникнут конфликты с существующими сервисами, порты нужно изменить на свободные.

### Настройка системы

В реальных условиях платформа работает в распределенном режиме. Для системной настройки кластера предполагается использование Ansible (см. https://github.com/blabtm/ops-eleven).

> Для ознакомительных целей можно настроить одну машину в локальном режиме:
> 
> ```bash
> task platform:sys:setup
> ```

### Развертка

Система готова к запуску:

```bash
task platform:deploy
```

Во время развертки будут созданы конфигурации, основанные на ранее заданных переменных.

### Настройка

Данный этап необходимо выполнять после "чистой" установки. Выполняется инициализация основных подсистем, создание сервисных аккаунтов, токенов и т.д.

```bash
task platform:setup
```

### Синхронизация

Платформа запущена и работоспособна, но в ней ничего нет. Для воспроизведения текущего состояния проекта требуется синхронизировать схемы, сервисы, визуализации и приложения:

```bash
task push
```

## Работа с сервисами

Для работы с сервисами существует менеджер сервисов. Он запускается как часть платформы и слушает REST. Для работы из терминала предусмотрен CLI клиент.

Для быстрого начала рекомендуется установить CLI клиент (поддерживаются `amd64` и `aarch64`):

```bash
curl -fsSL https://github.com/blabtm/v2k/releases/download/platform/sm/v0.0.0/install.sh | sh
export PATH=$HOME/.sm/bin:$PATH
```

Далее нужно обновить конфигурацию в `~/.sm/config.yaml` и установить адрес тестовой машины в локальной сети (тот, что установлен в переменной `LOCALHOST`).

Поддержка `Swarm` осуществлена не полностью, поэтому для проверки работоспособности платформы рекомендуется использовать сервис `sol.mf` (расчет магнитного поля соленоида), который настроен для работы на `Swarm`.

Помощь по CLI:

```bash
sm help
```

Просмотр доступных сервисов:

```bash
sm ls
```

Запуск `sol.mf`:

```bash
sm up sol.mf
```

Результат выполнения сервиса можно посмотреть в `blob/sol.mf`.
